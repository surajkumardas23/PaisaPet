# sample-sms.txt: SMS fixtures for Paisa Pet (SmsParser tests)
#
# Lines starting with # are comments. Write these fixtures BEFORE the parser.
# A test should loop over every block and compare the parser output with the expect fields.
# Only the text under "body:" is a real message. Every other line is test metadata that the app never sees.
#
# FORMAT
#   ### <ID>              block start. D = UPI debit, C = credit, X = other non-UPI-debit, S = synthetic edge case
#   sender: <id>          SMS sender. PLACEHOLDER IDs: replace with the real sender IDs from your phone
#   expect: DEBIT | IGNORE | DUPLICATE
#   amountPaise: <long>   DEBIT only. Money in paise, never floating point
#   merchant: <text>      DEBIT only. Payee exactly as the bank prints it (do not clean up)
#   date: <yyyy-mm-dd>    DEBIT only. The date printed in the message (day-month-year order as the bank writes it)
#   month: <yyyy-mm>      DEBIT only. Month the transaction must be filed under (month of the date in the message)
#   ref: <digits>         DEBIT only. UPI reference number
#   receivedAt: <ISO>     Optional. When the SMS reached the phone. If omitted, tests use the message date at 12:00 local
#   reason: <text>        IGNORE only. Why it must not become a transaction
#   duplicateOf: <ID>     DUPLICATE only. Same sender + body as an earlier block (same smsHash)
#   synthetic: true       Made up to cover an edge case. Everything else is based on real messages
#   note: <text>          Optional explanation
#   body:                 Message text starts on the next line and runs until a line containing only ---
#
# MASKING
#   Names, account/card digits, mobile numbers, reference numbers, order IDs, OTPs and link tokens are fake.
#   Wording, spacing, punctuation, casing, line breaks and truncation are kept exactly as received.
#   Bank helpline numbers and merchant names are public and left as is.
#   The account holder's name is masked as RAHUL SHARMA in every form it appears (RAHUL SHA, RAHULSHARMA).
#
# RULES THE FIXTURES ENCODE
#   1. Do NOT classify on the words "debited" or "credited" alone. An ICICI debit reads
#      "debited for Rs 620.00 ...; BIRRA BEVERAGES credited. UPI:..." so the word "credited" appears in a debit
#      (it refers to the payee). Use one template per bank and check which side of the sentence the account is on.
#   2. Debit wording differs by bank:
#        HDFC : "Sent Rs.304.00 from HDFC Bank A/c 4821 To <payee> <date> Ref <12 digits>"
#               A regular HDFC debit has 'On' before the date and writes the account as A/C *<last4>; an AutoPay one (D01) has neither.
#               HDFC has three debit wordings: 'Sent Rs.X From HDFC Bank A/C *1234 To <payee> On <date> Ref <12 digits>' (UPI ID or merchant), the AutoPay variant (D01), and 'HDFC Bank:Rs. X debited from a/c *1234 on <date> to a/c **5678 (UPI Ref No. <12 digits>)' (a bank account number; the payee is the printed account).
#        SBI  : "Dear UPI user A/C X3190 debited by 49.00 on date 28Sep26 trf to <payee> Refno <12 digits>"
#               (SBI prints the amount WITHOUT Rs/INR/rupee sign)
#        ICICI: "Acct XX518 debited for Rs 189.00 on 28-Jun-26; <payee> credited. UPI:<12 digits>"
#               (payee comes BEFORE the word "credited", reference follows "UPI:")
#   3. Amount shapes: "Rs.304.00", "debited by 49.00", "Rs 189.00", "Rs.5000" (no decimals), "INR 12,459.00" (commas).
#   4. Date shapes: 03/10/26, 28Sep26, 28-Jun-26, 21-10-26, 21/OCT/2026, 2025-11-09:11:32:58.
#   5. Payee shapes: truncated ("ZEPTO MARKETPLAC"), double space ("MOHAN  SINGH"), no spaces ("RentomojoPvtLtd"),
#      or the user's own name (self-transfer).
#   6. Card messages ("Card", "DEBIT/ATM Card") are never UPI, even when they say Spent/used/debited.
#   7. Failed or declined messages can contain the word "debited" but move no money.
#   8. UPI AutoPay / mandate: a message that reports money SENT is a normal UPI debit and is captured (D01).
#      Set-up and pre-debit notices move no money and are ignored (S07, S08) so one payment is never counted twice.
#      Never drop a message just because it contains the word "mandate".
#   9. Month filing: a transaction belongs to the month of the date printed in the message, not the month the SMS
#      arrived or was tagged (S09). Time of day comes from the SMS received time. If no date can be read,
#      the received time is used.
#  10. Multi-part SMS joining is tested at receiver level, not here. The parser only ever sees the joined body.
